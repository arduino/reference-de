= setWireTimeout

[#overview]
--

[float]
=== Beschreibung

Legt den Timeout für Wire-Übertragungen im Controller-Modus fest.

*Hinweis:* Diese Timeouts sind fast immer ein Zeichen für ein tieferliegendes Problem, etwa fehlerhaft arbeitende Geräte, Störsignale, unzureichende Abschirmung oder andere elektrische Probleme. Die Timeouts verhindern, dass dein Sketch hängen bleibt, beheben diese Probleme aber nicht. In solchen Situationen kommt es oft (auch) zu Datenfehlern, die keinen Timeout oder anderen Fehler auslösen und unerkannt bleiben. Wenn ein Timeout auftritt, sind also wahrscheinlich auch einige zuvor gelesene oder geschriebene Daten fehlerhaft. Unter Umständen sind zusätzliche Maßnahmen nötig, um solche Probleme zuverlässiger zu erkennen (z. B. Prüfsummen oder das Zurücklesen geschriebener Werte) und den Betrieb danach wiederherzustellen (z. B. ein vollständiger Neustart des Systems). Dieser Timeout und solche zusätzlichen Maßnahmen sind als letzte Verteidigungslinie zu verstehen. Wenn möglich, solltest du stattdessen die eigentliche Ursache beheben.

[float]
=== Syntax

`Wire.setWireTimeout(timeout, reset_on_timeout)`

`Wire.setWireTimeout()`

[float]
=== Parameter
* `timeout`: Timeout in Mikrosekunden. Bei null ist die Timeout-Prüfung deaktiviert.
* `reset_on_timeout`: Bei true wird die Wire-Hardware bei einem Timeout automatisch zurückgesetzt.

Wird diese Funktion ohne Parameter aufgerufen, wird ein Standard-Timeout eingestellt, der in einer typischen Konfiguration mit nur einem Controller ausreichen sollte, um ein Hängenbleiben zu verhindern.

[float]
=== Rückgabewert
Nichts.

[float]
=== Beispielcode

[source,arduino]
----
#include <Wire.h>

void setup() {
  Wire.begin(); // I2C-Bus beitreten (Adresse ist für den Controller optional)
  #if defined(WIRE_HAS_TIMEOUT)
    Wire.setWireTimeout(3000 /* us */, true /* reset_on_timeout */);
  #endif
}

byte x = 0;

void loop() {
  /* Zuerst einen Befehl an das andere Gerät senden */
  Wire.beginTransmission(8); // An Gerät Nr. 8 übertragen
  Wire.write(123);           // Befehl senden
  byte error = Wire.endTransmission(); // Transaktion ausführen
  if (error) {
    Serial.println("Error occurred when writing");
    if (error == 5)
      Serial.println("It was a timeout");
  }

  delay(100);

  /* Dann das Ergebnis lesen */
  #if defined(WIRE_HAS_TIMEOUT)
  Wire.clearWireTimeoutFlag();
  #endif
  byte len = Wire.requestFrom(8, 1); // 1 Byte von Gerät Nr. 8 anfordern
  if (len == 0) {
    Serial.println("Error occurred when reading");
    #if defined(WIRE_HAS_TIMEOUT)
    if (Wire.getWireTimeoutFlag())
      Serial.println("It was a timeout");
    #endif
  }

  delay(100);
}
----

[float]
=== Anmerkungen und Warnungen

Wie dieser Timeout umgesetzt ist, kann sich zwischen den Plattformen unterscheiden. Typischerweise wird ein Timeout aber ausgelöst, während auf den Abschluss (eines Teils) der Transaktion gewartet wird, z. B. darauf, dass der Bus wieder frei wird, auf ein ACK-Bit oder auch auf den Abschluss der gesamten Transaktion.

Tritt ein solcher Timeout auf, wird die Transaktion abgebrochen, und `endTransmission()` gibt einen Fehlercode bzw. `requestFrom()` null Bytes zurück. Das behebt das Problem auf dem Bus zwar nicht von selbst (ein Kurzschluss bleibt z. B. bestehen), verhindert aber zumindest ein möglicherweise endloses Blockieren und ermöglicht deiner Software, diesen Zustand zu erkennen und eventuell zu beheben.

Wenn `reset_on_timeout` auf true gesetzt wurde und die Plattform dies unterstützt, wird außerdem die Wire-Hardware zurückgesetzt. Das kann helfen, einen fehlerhaften Zustand im Wire-Hardwaremodul zu beseitigen. Auf der AVR-Plattform kann das zum Beispiel nötig sein, um die Kommunikation nach einem durch Störsignale verursachten Timeout wieder aufzunehmen.

Wenn ein Timeout ausgelöst wird, wird ein Flag gesetzt, das du mit `getWireTimeoutFlag()` abfragen kannst und mit `clearWireTimeoutFlag()` manuell zurücksetzen musst. Es wird auch beim Aufruf von `setWireTimeout()` zurückgesetzt.

Beachte, dass dieser Timeout auch ausgelöst werden kann, während auf das Ende eines Clock Stretchings gewartet wird oder darauf, dass ein zweiter Controller seine Transaktion abschließt. Passe den Timeout bei Bedarf so an, dass er auch diese Fälle abdeckt. Ein typischer Timeout wäre 25 ms (das maximale Clock Stretching, das das SMBus-Protokoll erlaubt), aber (viel) kürzere Werte funktionieren in der Regel auch.


[float]
=== Hinweise zur Portabilität

Diese Funktion war in der ursprünglichen Version der Wire-Bibliothek nicht vorhanden und ist möglicherweise noch nicht auf allen Plattformen verfügbar. Code, der über Plattformen und Versionen hinweg portabel sein muss, kann das Makro `WIRE_HAS_TIMEOUT` verwenden. Es ist nur definiert, wenn `Wire.setWireTimeout()`, `Wire.getWireTimeoutFlag()` und `Wire.clearWireTimeoutFlag()` alle verfügbar sind.

Als diese Timeout-Funktion auf der AVR-Plattform eingeführt wurde, blieb sie aus Kompatibilitätsgründen zunächst standardmäßig deaktiviert, in der Erwartung, dass sie später aktiviert wird. Der Standardwert des Timeouts kann sich daher zwischen Plattformen (und deren Versionen) unterscheiden. Die Standardeinstellungen für den Timeout stehen über die Makros `WIRE_DEFAULT_TIMEOUT` und `WIRE_DEFAULT_RESET_WITH_TIMEOUT` zur Verfügung.

Wenn der Timeout deaktiviert sein muss, empfiehlt es sich, ihn mit `setWireTimeout(0)` ausdrücklich zu deaktivieren, auch wenn das derzeit der Standard ist.
